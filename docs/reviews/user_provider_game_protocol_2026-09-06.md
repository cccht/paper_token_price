# 用户—厂家博弈与前后对比协议

本协议在新模型的结果计算前记录。用户目标：厂家通过分时价格引导用户自主换时、最大化个人效用；清晰展示算法使用前与使用后的结果。采用厂家同时公布价格、用户观察价格后进行拥塞博弈的两阶段结构。多个厂家在所声明的有限价格集合中竞争，用户层计算纯策略 Nash 均衡；不把这一结构称为同时行动的单阶段用户—厂家 Nash 博弈。

## 新模型边界

- 主实验为用户直连两家厂家；中间商保留为后续扩展，不套用旧 Logit 模型的结果。
- 每个用户请求代理有一个等工作量的归一化任务，必须选择一个厂家和一个可行时段。等任务量及共同 QoS 成本函数使用户子博弈具有可验证的精确势函数。
- 效用 = 固定任务价值 - 报价费用 - 时间延后成本 - 厂家切换成本 - 拥塞不效用。固定价值只确定效用零点，因此主要报告绝对效用差与广义成本变化，不用任意零点制造效用提升百分比。
- 释放时段等于原生时段；刚性请求不可延期，灵活请求可延期至截止时段。禁止提前到释放时段之前，不越过当日边界。
- QoS 仍使用既有测量拟合的指数曲线。容量为每时段归一化任务量参考，允许超载并反映为 QoS 损失；不把选定时段可行性等同于真实队列的完成期限保证。
- 所有执行任务按报价计费，厂家利润为收入减单位任务成本和固定容量成本。本新模型不采用旧稿的 QoS 计费折扣；新旧数值不可直接拼接。

## 预声明主配置

- 240 个请求代理、8 个三小时时段；原生时段分布来自仓库固定的 BurstGPT 平均负载形状。
- 容量 A/B = 30/12；任务价值 = 2 个归一化货币单位；共同 QoS 损失权重 = 2。
- 灵活份额 0.5，最多延期 2 个时段；每小时延期成本在 [0.01,0.03] 均匀生成，固定种子 20260906。
- 附加重复使用 20260907--20260910 四个种子，共五批合成用户；各批内部保持前后用户完全相同。统计合成实例间的差异，不将其当作真实市场抽样置信区间。
- 厂家偏好独立按容量比例抽取，切换成本 = 0.03；单位任务成本 A/B = 0.20/0.18，容量持有成本 = 每时段每参考容量单位 0.015。
- 分时价格 = base + slope x 零均值原生负载信号，整条报价须在 [0.30,1.35]。不通过截断改变均价。
- 三个嵌套菜单：base/slope 轴分别 3/3、5/5、9/9 个点，base 范围 [0.45,1.05]，slope 范围 [-0.30,0.30]。统一价为各菜单的零斜率子集。主报告采用最细菜单，粗菜单用于离散化比较。

## 均衡与选择规则

- 用户从相同的原生时段/偏好厂家开始，按预先固定的用户顺序作严格改进的最佳响应；平局保持当前选择。每次偏离包含用户自身加入新资源后的拥塞。
- 每次严格改进必须降低精确势函数。终止后穷举每个用户的所有可行偏离，最大效用改进不得超过 1e-8。
- 每个厂家价格对都独立重求用户均衡；不得通过沿用上一价格对的终态改变所声明的响应选择规则。
- 上层使用项目已有有限双矩阵均衡求解器，检查整个价格菜单中的厂家偏离收益。纯均衡有多个时使用固定字典序；没有纯均衡则计算并核验一个混合均衡。
- 所有离开上层支持的已声明价格对也必须通过用户均衡检查。厂家偏离时用户重新响应；用户偏离时厂家价格固定。

## 前后比较

1. **用户响应的算法对比**：给定相同的最终分时报价，原生安排（未求均衡）与自主最佳响应后的安排比较。明确前者不是均衡。
2. **公平的价格机制对比**：统一价格均衡与分时价格均衡；两边都求解用户 Nash，使用相同用户、容量和成本。
3. **均价约束对照**：两家均价固定为 0.75，分别比较固定价和允许斜率选择的价格子博弈。均价严格保持，单独报告该受限对照。
4. **用户顺序检查**：在最终支持价格对上使用额外用户更新顺序，报告用户均衡、效用和厂家支付的变化；未经重算，不把原厂家证书外推到另一响应选择规则。
5. **边界检查**：至少包括灵活份额 0.25/0.75 和窗口 1/2；每个对照中完整求解统一/分時两个博弈。计算预算与使用菜单在结果中明确。

## 图表与验收

- 同价格的用户响应前/后：净效用、广义成本、负载、QoS、时间延期与改用厂家比例。
- 统一均衡/分时均衡：期望用户净效用差、费用、延后成本、厂家利润、峰值与个体受益/受损比例。
- 用户逐时段可行净效用、选中时段及最大单边偏离；收敛图展示势函数和用户 regret，不要求总体效用在每一步都单调增加。
- 三层价格菜单结果与两家厂家最大偏离收益；有限菜单认证不等于连续价格域证明。
- 全部输出记录输入、代码 SHA、种子、用户顺序、候选价格及状态。即使最终变化不利或很小也保留完整结果。
